## How to ship a change (this is what worked)

1. Branch from an updated `master`. Make the change with tests.
2. Local gate: `npm test`, `npm run build`, `npx vitest run`, `npx playwright test`. If Playwright
   says the dev server timed out starting, run again once (slow right after a build). One
   role-tab test fails about one full run in six and retries itself.
3. Push with `git -c credential.helper= -c 'credential.helper=!gh auth git-credential' push`
   (the Windows credential helper hangs otherwise), open the PR, wait for the Cloudflare check
   (`gh pr checks <n>`; the status is the 2nd tab-separated column), merge with `gh pr merge <n> --merge`,
   then confirm the production build:
   `gh api repos/shivvrudra-cmd/beatmy11.com/commits/master/check-runs --jq '.check_runs[]|[.name,.status,.conclusion,.head_sha[0:7]]|@tsv'`
   (compare the sha with `origin/master`) and load the live page.
4. **Do not merge, leave for the owner:** scoring or difficulty changes they have not asked for,
   database migrations or new stored data, third-party scripts, the logo, legal text.
5. **Production database commands are blocked** in the owner's permission mode. Give the owner the
   exact command to run themselves.

## Traps (still true, plus new ones)

- Never guess stats, roles, names or nationalities. Unknown stays out and is listed.
- Hard rule: no individual player rating may be shown or readable from the screen.
- The draft screen and result screen 1 must stay exactly one phone screen tall
  (`tests/e2e/mobile-fit.spec.ts`, `tests/e2e/result-steady.spec.ts`).
- **Result page tests that scroll must send a touch first** (`window.dispatchEvent(new Event("touchstart"))`):
  before the first touch, the page undoes any scroll for 3 seconds.
- **Writing patch scripts through the shell:** the shell tool turns `\\n` in a heredoc into a real
  newline and `\n` is easy to get wrong. For anything with backslashes use the Edit tool, or build
  the character with `String.fromCharCode(92)`. Files here are CRLF on disk with LF in git: patch
  scripts must normalise (`replace(/\r\n/g, '\n')`) and restore. Fresh script file name each time,
  in `.test-dist/` (gitignored).
- `git add` files by name, never `git add -A <folder>`. Untracked on purpose: `.claude/worktrees/`,
  `docs/previews/`, older `docs/marketing/launch-posts*.md`.
- Two test runs at once share one dev server and break each other. Run one at a time.
- Never run `npx astro check` unattended (it waits for a prompt).
- After any change to pools, scoring or opponents, re-run `scripts/cricsheet/calibrate-white-ball.ts`
  (build with esbuild first, see its header) and commit the regenerated `*-series.json`.
- Check header or security-policy changes on the live site after the deploy
  (`node scripts/check-live-headers.mjs https://beatmy11.com`; it can take over a minute).
- A shell `sleep` followed by another command is blocked; wait with an `until` loop instead.
- Testing on iPhone-like WebKit: see the checklist status block. Do not commit that config change.
