## How to ship a change (this is what worked)

1. Branch from an updated `master`. Make the change with tests.
2. Local gate, all on **one** command line so nothing merges if a step fails: `npm test`,
   `npm run build`, `npx vitest run`, `npx playwright test`. If Playwright says the dev server
   timed out starting, run again once (it is slow right after a build). The helper scripts
   `.test-dist/check.sh` and `.test-dist/ship.sh` do this but are gitignored: recreate them if
   missing (`check.sh [noe2e]` runs the gate; `ship.sh <title> <body-file> [nomerge]` pushes,
   opens the PR, waits for Cloudflare's check, merges, then checks the production build).
3. Open a PR, wait for the Cloudflare check (`gh pr checks <n>`), merge with
   `gh pr merge <n> --merge`, then confirm the production build:
   `gh api repos/shivvrudra-cmd/beatmy11.com/commits/master/check-runs --jq '.check_runs[]|[.name,.status,.conclusion]|@tsv'`
   and load the live page.
4. **Do not merge, leave for the owner:** scoring or difficulty changes they have not asked for,
   database migrations or new stored data, third-party scripts, the logo, legal text. (They have
   explicitly asked for the items in the checklist; changes to the series ladder for item 5 are
   asked for, but say what changes in the win rate.)
5. **Production database commands are blocked in the owner's current permission mode** (auto).
   Give the owner the exact command to run themselves. Do not try to work around it.
